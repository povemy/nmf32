Task: Phase 2.4 / C2.2 — fix the main marketplace search endpoint (case-sensitive substring
matching, not using the shared tokenized engine). Preserve submit-only UX, cache-key
protection, filters/pagination; add pg_trgm migration (NOT applied).

  `src/app/api/_shared/search.ts` — actual path is market-scoped; `src/app/api/_shared/`

- The MAIN search route is **`GET /api/market/products?search=`** (the results page;
  `market/search/` contains only `suggest/` + `related/` subroutes — there is no

## Changes

### 1. `src/app/api/market/products/route.ts` (the C2.2 fix)
- Uses the shared engine: `tokenize()` + `buildTokenWhere()` → every token must hit ≥1 of
  **title, description, category.name, store.name**, case-insensitive (`mode:"insensitive"`
  → ILIKE), multi-word in any order. `%` wildcards in tokens preserved (engine's partial
  matching).
- **`sort=relevance` ("Best match")**: deterministic candidate window (top
  `RELEVANCE_CANDIDATE_CAP=200` matches by `salesCount desc, id asc`), in-memory
  `scoreProduct` ranking, tiebreak chain **score ▸ salesCount ▸ ratingAvg ▸ createdAt ▸ id**
  (final unique `id` ⇒ fully deterministic pages), page sliced from the ranked list,
  `total = min(count, 200)` so "Load more" never promises rows the window can't serve.
- ALL standard SQL sorts now append `{ id: "asc" }` (unique tiebreaker) — deterministic
  pagination (previously createdAt/price/sales ties could reshuffle between pages).
- PRESERVED: category filter (incl. children expansion), liveStore + C1.3 seller-status
  defense-in-depth, `{data, meta}` envelope, `publicCache` wrapper verbatim
  (`["market-products"]`, TTL 45s, tag `pub:products`, same arg tuple → same invalidation
  semantics), `normalizeSearchQuery` guard at the route boundary (cache-key protection).

### 2. `src/components/shopper/market.tsx` (minimal frontend, per S1 intended design)
- `SORTS` + `{ value: "relevance", label: "Best match" }` — shown ONLY in search mode.
- Initial sort: `mode.kind === "search" ? "relevance" : "newest"` (shell remounts
  ResultsView per submitted query — key includes `q` — so each new search re-seeds it).
- Sort change now resets `page` to 1 (was a latent bug: page N of the new sort got
  APPENDED to the old sort's items).

### 3. Suggest/related routes — NO functional change (net zero diff vs pre-session state)
- **Frontend trigger audit**: grep across `src/components` + `src/app` found **ZERO
  frontend callers** of `/api/market/search/suggest` (and of `/related`). The shopper
  header search (`shopper-shell.tsx:786-793`) is **submit-only**:
  `onKeyDown Enter → submitSearch()` → `nav({name:"search", q})` — no dropdown, no
  debounce, no per-keystroke requests. The Phase-2.1 "no-autocomplete" hardening already
  removed the old combobox. **Requirement already satisfied; nothing to change.**
- I initially "fixed" a description gap (`include: {…productCardInclude, description: true}`)
  in suggest/related believing `scoreProduct`'s description weights were dead — WRONG:
  Prisma `include` returns ALL scalar fields (description included) by default; scalars
  are NOT valid inside `include` (tsc + runtime reject them). Fully reverted; the engine's
  description weights were never dead. Net diff on those two files = the pre-existing
  C1.3 changes from an earlier phase only.

### 4. Engine review (`market/_shared/search.ts`) — NOT broken, kept as-is
- `tokenize` (≤8 tokens, `%` preserved), `scoreProduct` (phrase 60 ▸ all-tokens-title 30 ▸
  per-token title 20 / category 8 / store 6 / desc 3, popularity/rating nudges),
  `buildTokenWhere` (AND-of-token-hits), `buildAnyTokenWhere` (OR, related route) — all
  sound. Brand (`Product.sourceBrand`) is NOT an engine field — left out deliberately
  (import-source metadata, mostly NULL for native listings).
- Doc-vs-impl note (`src/lib/search-normalize.ts`): comment claims over-length → empty;
  implementation actually TRUNCATES to 80 chars (a 100-char query searches its first 80
  chars → typically 0 results, NOT the unfiltered listing). Cache safety (the actual
  Phase-2.1 goal) holds either way — key bounded at 80 chars. Behavior kept identical
  (shared with `sf/[slug]/products`); documented, not changed.

### 5. `prisma/migrations/20261109000000_phase24_search_indexes/migration.sql` (NOT applied)
- `CREATE EXTENSION IF NOT EXISTS pg_trgm;` + GIN trigram indexes on the EXACT columns the
  tokenized queries filter: `Product.title`, `Product.description`, `Store.name`,
  `Category.name` (Store.name also serves suggest's direct store-leg ILIKE).
- Supabase note (extension usually available; run as owner if role lacks rights),
