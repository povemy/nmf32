# P2.2-8 — Phase 2.2, C3: Marketplace OAuth Connection Ownership

Task: verified audit fix — marketplace connections must be associated with the
correct seller; the import runner must never pick another seller's connection
because it is the most recently created; claim/bind must not capture other
sellers' connections. Audit ID **C3** referenced in every code comment.

Context for later agents: schema was already prepared by the lead engineer
(`MarketplaceConnection.sellerId String?` + `@@index([sellerId])`, migration
`prisma/migrations/20261105000000_phase22_marketplace_integrity/migration.sql`
NOT applied). Because the dev DB lacks the column, every
`MarketplaceConnection` read/write now uses an explicit `select` (excluding
`sellerId` unless the code path genuinely needs it — those paths are
verification-pending until the migration is applied and the dev server picks
up the regenerated client).

## Runner connection-selection scoping (exact)

```
sellerId = job.claimedById
if (!sellerId) throw 409 NO_CONNECTION            // fail closed — NO global fallback
owning   = db.seller.findUnique({ where: { id: sellerId },
           select: { store: { select: { id: true } } } })
storeId  = owning?.store?.id ?? null
conn = db.marketplaceConnection.findFirst({
  where: { platform: job.platform, status: "connected",
           OR: storeId ? [{ sellerId }, { storeId }] : [{ sellerId }] },
           // storeId clause ONLY when non-null — literal `storeId: null`
           // in Prisma means IS NULL and would match ANY unbound connection
  orderBy: { createdAt: "desc" }, select: { id: true } })
if (!conn) throw 409 NO_CONNECTION
```

Fixture branch above it is unchanged (upserts its own pseudo-connection,
already `select: { id: true }`, no sellerId → fully runtime-safe pre-migration).

## claim/bind ownership rules (exact)

Lookup (oauth_shopee / oauth_tiktok verification):
```
findFirst({ where: { platform, status: "connected",
                      shopId: job.sourceShopId ?? undefined,
                      OR: [{ sellerId: session.userId }, { sellerId: null }] },
            orderBy: { createdAt: "desc" },
            select: { id, shopId, shopName, sellerId } })
```
then the pre-existing post-check `!conn || !job.sourceShopId ||
conn.shopId !== job.sourceShopId` → 403 OWNERSHIP_NOT_VERIFIED. Net rule:
shopId must match the imported shop AND the connection must be the claiming
seller's own (attributed) or a legacy unattributed row.

Post-claim bulk-bind (was: attach ALL unbound connections of the platform):
```
updateMany({ where: { platform: job.platform, storeId: null,
                       OR: [{ sellerId: session.userId },
                            { sellerId: null, shopId: job.sourceShopId }] },
             data: { storeId: result.id } }).catch(() => undefined)
```
Only the claimer's OWN unbound connections + legacy unattributed rows
matching the imported shop get attached. Fixture connections (sellerId null,
shopId = fixture slug) still bind for claim_code claims.

## sellerId flow: begin → callback → exchangeCode

1. `GET /api/store/connections/[platform]/begin` (unchanged) stores
   `{ sellerId, platform, createdAt }` under `oauth_state_{nonce}` (Setting
   table) and puts the nonce in the OAuth `state` param.
2. `GET /api/auth/callback/[platform]` validates the nonce fail-closed (F-22:
   single-use delete-first, platform match, 10-min TTL, sellerId-vs-session
   cross-check) and passes `meta.sellerId ?? null` to `exchangeCode`.
3. `exchangeCode` persists it on `create` (and legacy-attributed update).

## Deliberate non-changes

- `store/connections/route.ts` sellerId display: NOT added — the list is
  already store-scoped (F-20), sellerId isn't needed, and adding it would
  make the endpoint fail during the pre-migration window.
- `authStatus()` platform-global connected flag: left global (signature has
  no seller context). Worst case a seller without their own connection sees
  the job start "queued" and then fail closed 409 NO_CONNECTION — honest
  failure, no cross-seller leak.
- No `shopId` preference inside the seller-scoped lookups (consistent with
  the prescribed plan; within-seller multi-shop selection stays most-recent).
- `claimedById` NOT set at job creation (would break claim/bind's
  ALREADY_CLAIMED guard and the store binding workflow); connectionId pinning
  used instead.
- Runner.ts: only the connection-selection block touched; the lead's C1.4
  moderation edits in the same file were left alone.
- No prisma db push/migrate, no direct DB connections, no git commits.
