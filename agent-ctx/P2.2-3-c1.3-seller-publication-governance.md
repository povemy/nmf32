# P2.2-3 — Phase 2.2 / C1.3 seller publication governance (audit fix)

Task ID: P2.2-3. Scope: verified audit fix for two conflicting seller/store
publication mechanisms that let ineligible sellers go publicly live.
Next.js 16 App Router + TS + Prisma. Dev server left running (port 3000).

## Verified finding (re-confirmed before fixing)
- `src/app/api/store/publish/route.ts` blocked only suspended/terminated sellers;
  `canPublish()` in `src/lib/store-lifecycle.ts` checked store fields only — never
  `seller.status` / `seller.kycStatus`.
- All 5 admin seller routes wrote `store.status` via raw `db.store.update`,
  bypassing the `transitionStore` state machine (grep confirmed these are the
  only direct store-status writes outside claim/import flows).
- No public query checked `seller.status` — visibility was decided solely by
  `store.status === "live"` + `product.status === "active"`.

## Changes made (17 files)

### 1. `src/lib/store-lifecycle.ts`
- `canPublish(storeId)` now includes `seller: { select: { status: true } }` and
  FAILS CLOSED: if the store has a `sellerId` whose seller is missing or not
  `status: "active"`, returns `{ ok: false, code: "SELLER_NOT_APPROVED", blockers }`.
  `sellerId: null` keeps the existing "must be claimed" blocker (still unpublishable).
  `PublishCheck` gained optional `code?: string`. kycStatus deliberately untouched.
- Added `ADMIN_PATHS` + exported `planAdminStorePath(current, to)` and
  `transitionStoreToward({ storeId, to, actorId, note })`: admin seller routes
  reach their target store status through LEGAL transitions only.
  - to `live`: draft→live; maintenance→live; suspended→draft→live; claimed→draft→live.
  - to `draft`: live→draft; maintenance→suspended→draft; suspended→draft; claimed→draft.
  - Pre-claim statuses (generating/pending_verification/pending_claim) and
    archived have NO path → TransitionError → route maps to 409 (a pending_claim
    store needs claiming first; admin must not fabricate claim/configure steps).
  - Already-at-target ⇒ no-op ([]). Every hop journaled via transitionStore
    (actorType "admin"), CAS-guarded against concurrent transitions.

### 2. `src/app/api/store/publish/route.ts`
- Explicit belt-and-braces 403 blocks with distinct codes BEFORE canPublish:
  `SELLER_ONBOARDING`, `SELLER_PENDING_REVIEW`, `SELLER_REJECTED`, plus a
  `SELLER_NOT_APPROVED` catch-all for any other non-active status. Existing
  suspended/terminated blocks kept. Gate failure with `code === "SELLER_NOT_APPROVED"`
  answers 403; other gate failures keep 422 PUBLISH_BLOCKED.

### 3. Admin seller routes — all 5 now route through the machine
- `approve/route.ts` → target `live` (note "seller approved")
- `activate/route.ts` → target `live` (note "seller activated")
- `reject/route.ts` → target `draft` (note "seller rejected: {reason}")
- `suspend/route.ts` → target `draft` (note "seller suspended: {reason}")
- `terminate/route.ts` → target `draft` (note "seller terminated: {reason}")
Pattern per route: pre-validate with `planAdminStorePath` and 409 BEFORE the
seller row is mutated (no partial state); after `db.seller.update`, apply via
`transitionStoreToward`, catching `TransitionError` → 409 CONFLICT (other errors
rethrown). Session revocation (reject/suspend/terminate), notify, logActivity,
auditAdmin before/after shapes — all unchanged and still accurate (final store
status equals the target on every success path).

### 4. Public filters — `seller.status: "active"` added (defense-in-depth)
- `market/products/route.ts` — liveStore seller sub-filter.
- `market/home/route.ts` — liveStore seller sub-filter + featuredStores query.
- `market/search/related/route.ts` — liveStore seller sub-filter.
- `market/search/suggest/route.ts` — product where + store suggestion where.
- `market/stores/route.ts` — directory where.
- `sf/[slug]/route.ts`, `sf/[slug]/products/route.ts`,
  `sf/[slug]/products/[pSlug]/route.ts` — store lookup switched from
  `findUnique({ slug })` + JS status check to `findFirst({ slug, status: "live",
  seller: { is: { status: "active" } } })` (slug stays the key; inactive seller ⇒
  same 404 notFound path — fail closed). Cache tags/TTLs untouched.
- `src/app/sitemap.ts` — stores where gains the seller filter.
- `checkout/pricing.ts` — variant query's store select gains
  `seller: { select: { status: true } }`; eligibility check at ~line 284 adds
  `v.product.store.seller?.status !== "active"` (null/unlinked seller ⇒ ineligible).
- `cart/stock/route.ts` — same: seller status in select; `purchasable` gains
  `&& v.product.store.seller?.status === "active"`.
