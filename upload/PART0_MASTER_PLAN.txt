--------------------------------------------------------------------------------
0.1 ONE-LINE DEFINITION
--------------------------------------------------------------------------------
A free-to-join, commission-based e-commerce platform where every seller gets an
instant standalone storefront (own domain optional) AND automatic placement in a
shared marketplace — like "Shopify + Shopee in one", with zero setup cost for
founders. Platform earns via configurable profit-sharing (commission) per sale.

--------------------------------------------------------------------------------
0.2 CORE CONCEPT (LOCKED DECISIONS)
--------------------------------------------------------------------------------
1. Standalone platform (self-hosted / own infra, not built on Shopify).
2. General e-commerce — any legal product, any seller. Risk is handled via
   moderation + prohibited-items policy + risk tiers (see PART 1 §1.11),
   NOT by niche restriction.
3. Business model: FREE plan (no monthly fee, no setup fee). Platform takes a
   commission per order, pre-configured in admin backend (global default,
   per-category, per-seller, per-product overrides + fee holidays).
4. Built-in page builder — founders with zero tech skill can launch a store.
5. Seller onboarding REQUIRED: register -> KYC -> admin approval -> store live.
6. Sellers self-serve store setup via fast onboarding wizard + page builder.
7. Local payments first (gateway-abstracted; e.g., MY: FPX/TNG/GrabPay via
   Curlec/ToyyibPay/Stripe-MY; ID: Midtrans/Xendit). Cards can ride the same
   abstraction later.
8. Custom domain support: CNAME mode AND full nameserver delegation mode.
9. Integration-ready: per-store marketing pixels (Meta/GA4/TikTok/GTM),
   outbound webhooks, and a public REST API (works with Zapier/Make).
10. Admin backend = command centre. Every operational knob, every log, every
    state is controllable/observable from admin. Nothing requires DB access.

0.7 GLOBAL CONVENTIONS (apply to ALL parts)
--------------------------------------------------------------------------------
- Money: BIGINT minor units + CHAR(3) currency. NEVER floats. Helper: minor(x).
- Time: TIMESTAMPTZ, UTC everywhere; render in store.timezone.
- IDs: UUID v4 (gen_random_uuid). Human refs: order_number, payout reference_no.
- Soft delete: deleted_at TIMESTAMPTZ on catalog/store tables; orders/money
  rows are NEVER deleted (immutable + reversing entries).
- Enums: TEXT + CHECK constraints (easy migration), documented in DDL.
- Pagination: page/size (max 100) + total; cursor for ledger/webhook logs.
- Errors: { "error": { "code": "MACHINE_CODE", "message": "...", "details": {} } }
- Idempotency: Idempotency-Key header REQUIRED on POST that moves money.
- Naming: DB snake_case; API camelCase; mapping is mechanical (see PART 5 §5.2).
- Secrets: app-level AES-256-GCM for *_enc columns; keys in KMS/env.
- Audit: EVERY admin mutation writes admin_audit_logs with before/after JSONB.
  Enforced by an API interceptor, verified by nightly job (PART 6).

--------------------------------------------------------------------------------
0.8 BUILD PHASES (suggested, 2-person team)
--------------------------------------------------------------------------------
Phase 0 (wk 1-2)   Infra, CI (PART 6), auth (admin+seller), tenancy skeleton,
                   admin shell + audit interceptor.
Phase 1 (wk 3-5)   Catalog, media, page builder + section renderer, storefront
                   SSR + caching, seller dashboard v1.
Phase 2 (wk 6-8)   Cart, checkout, payment driver + first local gateway,
                   orders pipeline, emails.
Phase 3 (wk 9-10)  Commission engine, wallets, double-entry ledger, payouts.
Phase 4 (wk 11-13) Marketplace discovery + search, custom domains, integrations
                   (pixels, webhooks, public API), notifications, coupons.
Phase 5 (wk 14-15) Reports/exports, support desk, RLS, hardening, load test,
                   restore drill, LAUNCH.
MVP cutline: Phases 0-3 + minimal admin = launchable with manual marketplace
curation and manual payouts.
